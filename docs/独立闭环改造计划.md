# 长流独立闭环改造计划（0.8.4 → 0.9）

> 目标：不依赖任何外部 App / 桌面端 / 第三方配对，内部四模块（底座、一手、总控、中枢）从"同进程拼装"变成一条闭合链路。

## 一、已落地（本次改动，已编译验证）

### 1. 拦截决策链：三链抢答 → 单管道

| 项 | 落点 |
|---|---|
| 关卡纯逻辑 + 单测 | `core/src/main/kotlin/com/changliu/core/hub/GatePlan.kt`、`core/src/test/.../GatePlanTest.kt`（10 项） |
| 单管道编排 | `app/.../hub/policy/GateDirector.kt` |
| 旧入口退化为委托 | `app/.../hub/policy/HubPolicy.kt` |
| 唯一出口 | `ChangliuA11yService.onAccessibilityEvent` → `GateDirector.intercept` |

排序：名单（`hub/constraints.json`）→ 总控定级（信用分 / 严管 / 总控时间 / `PassPolicy.hold` / `passCap`）→ 关卡。

档位规则（`GatePlanner`，纯函数）：

| 输入 | 关卡 | 轮数 | 放行 |
|---|---|---|---|
| 总控时间 | L4 HQ | 0 | 0 |
| 专注锁 / 严管 / 直接拦 | L4 BLOCK | 0 | 0 |
| 信用 < 40 | L4 BLOCK | 0 | 0 |
| 信用 40–59 或 OBSERVE | L3 证据核验 | 1 | 3 分钟 |
| 信用 60–69，或当日第 3 次开 | L2 专项闯关 | 2 | 5 分钟 |
| 信用 ≥ 70 | L1 断点快答 | 1 | 设置值（≤10） |

`passCap > 0` 时压到该值；封死时恒为 0 分钟。

### 2. 闸门页按关卡跑

`app/.../infra/gate/GateActivity.kt`：新增 `intent(ctx, pkg, plan)` 重载；页眉标注关卡；L2 连过两轮才放行（`passedRounds` 参与 `onSaveInstanceState`）；L3 多一个「去语音陪练拆一步」入口直连 `WindowActivity(startNow)`；放行分钟取 `min(plan.minutes, 设置值)`。

### 3. 放行期 1 秒巡检

`ChangliuA11yService.passWatcher`：只有存在有效放行条（`blocking.allowedUntil` 未过期）时才每秒读一次前台包名，抓到事件流被 ROM 吞掉的切换，走同一条 `GateDirector` 判定。无放行条时完全不读窗口。

### 4. 四部 → 一手自动炼题

`app/.../hub/sync/MaterialSync.kt`：脉络里 `status=假设` 且未同步过的节点，落成一手的素材（title + claim + note + 验证方式），记 `SharedPreferences hub_sync/vein_seen` 去重，单次上限 20 条。挂在 `KeepAliveService` 已有的 10 分钟后台块里（该块本身跑在 `Thread` 上，不占主线程）。

不自动造四选一题卡：没有真实干扰项的题是假题，宁可让 `QuestionRouter` 用"素材 + 模型"现场出。

### 5. 切断外部入口 / 收口导出

- `MainActivity.linkCard()`：删除"复制安装说明 / 填配对码"的桌面端引导，改为「外部配对入口已关闭，去配网关」。
- `app/src/debug/AndroidManifest.xml`：移除 4 个 `exported=true` 的调试 Activity（Memory / UnifiedSettings / Constraints / Conductor），只留 `DebugNudgeReceiver`（`adb broadcast` 验 L0/L1 用）。

导出组件核对（新包）：`ChangliuShellActivity`、`DebugNudgeReceiver`、`ShareActivity`、`BoardWidget`、`PetWidget`、两个 `BootReceiver`、`RescheduleReceiver` —— 其余全部收进包内。

### 6. 防线在界面上可见（收官 P1）

以前信用分和关卡只存在于拦截那一刻，用户在壳里看不到"现在有多紧"。补了三处：

- `GateDirector.zone(ctx)`：假定此刻打开一个受控 App 会走哪一关、给几分钟。和 `intercept` 用同一个 `GatePlanner`，不是一个新规则。
- 首页新增「防线 · Lx」卡片：关卡 + 信用分 + 放行分钟 + 一句原因，外加「四部 → 一手：已装弹药 N 条 / 待炼 M 条」——把自动炼题管道也摆到台面上。
- 数据页「今天」新增「防线」格：当前档位 + 信用分（起点 70），和拦截次数并排。
- `ShellSnap` 增 `credit / gateLevel / gateLabel / gateMinutes / gateReason / veinFed / veinPending`，仍由 `ShellData.read` 在 IO 线程一次取完。

### 7. 训练页复活高频组件

`TrainScreen` 新增「现在练一手」两组四张卡，全部接现有路由，没有新页面：

| 卡片 | 落点 |
|---|---|
| 舒尔特方格 | `yishou:schulte` |
| 残局 | `yishou:endgame` |
| 预判本 | `yishou:bets` |
| 刷屏做题 | `ScrollActivity.startIntent` |

这四张就是过闸时被问的东西——「在训练栏练的」和「被拦时考的」是同一批组件。

## 二、未做的与原因

| 规格项 | 状态 | 原因 / 下一步 |
|---|---|---|
| ScrollService 放行后"强制挂载" | 半做 | `MediaProjection` 必须每次用户同意，无法静默挂。当前做法：L2/L3 放行后直接拉起 `ScrollActivity` 授权页；拒绝即退化为无伴读。若要更硬，改为"拒绝则扣减下次放行分钟"。 |
| 桌面组件（BoardWidget / PetWidget）复活 | 未做 | 清单里仍在，没有"有效手数 → 放风额度"的结算。落点：`HubStats` 加一组有效手数 → `GatePlan.minutes` 加成。 |
| 收集箱本地化（切断 Notion） | 未做 | 收集箱当前是 Notion 库（`inboxDb`）。要做到 100% 独立，需要本地 `inbox` 表 + 迁移，属于独立一轮改动。 |
| 五栏重组 | 已做（首页/数据） | 首页防线卡 + 数据页防线格已完成；四部页的「一键转入一手题库」按钮未做（后台管道已经自动跑，按钮是让过程可见）。 |
| T3 确认 + 24 小时生效 | 未做 | `core/hub/ToolPolicy.kt` 已有 T0–T3 分级，缺的是"确认后延迟生效"的落地存储与倒计时。 |
| 语音陪练在 L3 自动降阶 | 半做 | 现在是按钮入口，未做"连续答错 N 次自动拉起"。 |
| 秒级巡检的精度 | 已知上限 | 1 秒轮询 + 事件驱动；极端情况（<1 秒切入切出）仍可能漏。`shortcut: 1s 轮询, 需要 <1s 精度时改用无障碍事件 + 截帧校验`。 |

## 三、下一步优先级

1. **P1**：`ScrollService` 授权失败 → 扣减放行（把"伴读"变成有代价的选项）。
2. **P1**：收集箱本地化（`hub/inbox`），彻底去掉 Notion 依赖 —— 这是"100% 独立"最后一条外部数据线。
3. **P2**：桌面组件接统一结算（有效手数 → 放风额度加成）。
4. **P3**：T3 24 小时延迟生效中心。
5. **P3**：四部页「一键转入一手题库」按钮（后台管道已自动跑，按钮只为让转化过程可见）。
