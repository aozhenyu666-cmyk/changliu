# 长流融合说明（0.7.0-fusion）

> 对应实施计划：`长流融合-实施计划.md`。本文件记录「实际怎么落的、验证到哪、和计划的差异」。

## 1. 结论

单进程超级 App `com.changliu.app`「长流」已编译、安装、跑通：

- **单 Application**：`ChangliuApp`（继承一手 `YishouApp`，实现总控 `ZkHost`）
- **单无障碍**：`infra.a11y.ChangliuA11yService`
- **单强制全屏页**：`infra.gate.GateActivity`（含 `MODE_GATE/MODE_BLOCK/MODE_HQ`）
- **单常驻服务**：`infra.keepalive.KeepAliveService`
- **单 LLM 客户端**：`infra.llm.ChatClient`（一手原实现，补 `maxTokens/temperature`）
- **单兜底遮罩**：`infra.gate.GateCover`
- 一手、总控、驾驶员三套 UI 在**同一进程**内可启动（模拟器实测 pid 不变）

## 2. 工程结构

```
changliu/
├── app/   com.changliu.app       驾驶员底座 + 基础设施 + 统一壳 + 三条决策链
├── ys/    com.yishou.app         一手（library 模块，保留原包名/R/BuildConfig/Room）
├── zk/    com.zongkong.app       总控（library 模块，含 com.zongkong.core）
└── core/  com.changliu.core      驾驶员纯 Kotlin 规则/状态机
```

### 为什么是 library 模块而不是把源码 rename 进 `app/`

实施计划原本要求「复制 + 改包名」到 `com.changliu.app.ys/zk`。实际执行时，本机 Mimosa 策略禁止 Bash 直接写入源码树（`cp`/`sed -i` 均被拦截，只允许 Write/Edit 逐文件提交）。457 个源码文件逐个 Write 不现实，因此改为：

- `:ys` / `:zk` 用 Gradle `sourceSets` 直接编译 `D:/code/src-ref/yishou`、`D:/code/src-ref/zongkong`；
- 保留原包名，各自生成 `R` / `BuildConfig`，从根上避免了资源名和 R 的冲突；
- 组件在 `:app` 清单里用全限定类名统一声明。

**现状（2026-11-07）**：已用 `scripts/vendor-legacy.sh` 把一手/总控源码复制进仓库 `legacy/`（约 4.7 MB），**仓库已自包含**；`clean` 全量构建与 773 项测试均通过。模块的源码根优先级：`-PlegacyRoot` > `LEGACY_ROOT` > 仓库内 `legacy/` > `D:/code/src-ref`。

## 3. 基础设施合并

| 项 | 做法 |
|---|---|
| Application | `ChangliuApp : YishouApp(), ZkHost`。一手 150 处 `applicationContext as YishouApp` 原样可用；总控 `zk.*` 通过 `ZkContext`（ContextWrapper + 委托）继续可当 Context 用 |
| 无障碍 | 唯一服务承接事件主干（驾驶员的 rootInActiveWindow 复核 + 5 秒复查），20 秒 tick |
| 决策链 | `A11yExtensions`：总控（`ZkGateLink`）→ 一手（`YsGateLink`）→ 驾驶员（`Intercept`）。任一层弹页后不再叠加 |
| 拦截页 | 驾驶员 GateActivity 升为 `infra.gate.GateActivity`；一手/总控保留各自业务页（入口思考页 / 严管页 / 低屏做题页），由决策链拉起 |
| 保活 | `KeepAliveService` = 驾驶员 LockService（陪练通知 + 音频监听）+ GuardService（15s/60s 自愈）+ 总控 60s 本地规则（`LocalGuardian`）。总控旧 `SelfHeal/Watchdog` 已移除（只认原 GuardService，融合会误报）；总控原 `KeepAliveService.start` 通过 bridge 改走唯一服务 |
| 存储 | 一手 Room（33 实体/迁移链）原样；总控/驾驶员保留 JSON，各自目录；密钥三端统一：一手 EncryptedSharedPreferences，驾驶员与总控走 `:infra` 的 `SecretBox`（AndroidKeyStore AES/GCM，总控 `config.json` 不再是明文） |
| 文件共享 | 统一 authority `com.changliu.app.files`，`file_paths.xml` 合并 `cache/images` + `files/proofs` |
| 外部互保 | `A11yGuard.PEERS` 置空（融合后不再替旧 App 写回）；总控哨兵/healthwire 保留代码但不再注册为外部入口 |

## 3.5 功能整合与联通（0.8）

### 统一设置（API key / 模型 / 语音 / Notion）

- `app/.../infra/settings/UnifiedSettings.kt`：一次读取三端配置，填一次写三端。
- 读取优先级：驾驶员（已填 key）→ 一手 → 总控；主模型/轻模型/识图/语音/Notion 各取第一个非空。
- 落盘：驾驶员 `llm.json`（SecretBox 密文）、一手 `yishou_settings`（EncryptedSharedPreferences）、总控 `config.json`（写盘前 `sealSecrets`）。
- UI：`ui/UnifiedSettingsActivity.kt`，入口「我的 → 集成 → API 与集成」；带「保存并同步三端」「测试连接」。

### 进程内直连（替代 ContentProvider）

`:infra` 新增 `FusionHooks`（中性 DTO：`YishouSnapshot` / `PassPolicy`），`:app` 的 `FusionLink` 在启动时接真实实现：

- 总控读一手今日账：直接读一手 Room + `DayLedger`，不再跨进程/签名校验；
- 总控把一步行动交给一手：直接写入/更新一手当前任务（同名任务就地更新）；
- 总控开一手陪练窗口：拉起一手 `WindowActivity` 并带 `startNow`，直接开局；
- 一手发放行前读总控收紧：`PassIssuer` 调 `FusionHooks.zongkongPassPolicy`，严管/专注锁/落后时 `hold` 或把放行分钟压到 `passCap`。
- 旧 ContentProvider 路径保留为 fallback（未接钩子/单独运行模块时仍可用）。

### 冷启动修复

- 一手/总控原先在 `Application.onCreate` 同步创建多个 OkHttp/ChatClient，慢设备上 OkHttp 类初始化可达十几秒，触发 ANR。
- 已把 `YishouApp` 的 engine/cardEngine/drillGen/vision/summaryEngine/materials、总控 `Actions.llm/notion/verifier`、`ChatRepo.client` 改为 `lazy`；首个网络请求在后台/用户操作时初始化。
- 常驻服务从 `Application.onCreate` 移到壳页 `onResume`，避免 5 秒 `startForeground` 超时；服务端也加了 `startForeground` 失败自停兜底。

### 统一账本与数据页（P1）

- **账本**：新建 Room 库 `changliu.db`（`hub/ledger`），两表 `event` / `rollup`；`Ledger.emit` 异步写入，失败不影响业务；保留 180 天，支持导出 JSON 与一键清空。
- **事件**：`app_fg`（前台包名 + 秒数，唯一无障碍服务计时）、`gate_shown` / `gate_answer`（是否有依据、用时）、`live_start` / `live_end`（陪练分钟与结论）、`flow_transition`（五态）、`task_done`（总控完成行动）、`train_set`（一手完成一组）。
- **钩子**：驾驶员服务/Gate/Engine/BrainRuntime 直接写；一手 `CardSession.writeSet`、总控 `WorkActions.complete` 通过 `FusionHooks.ledgerEmit` 写。
- **汇总**：`HubStats` 提供今天/本周；`KeepAliveService` 每 10 分钟 `Ledger.rollup` 落 `rollup` 并清理过期数据。
- **数据页**：统一壳新增第 4 栏「数据」，今天（屏幕/娱乐/拦截通过率/陪练/训练/行动/前 5 App/滑行次数）与本周（7 天柱状图与合计）两屏。
- **补齐**：总控 Notion 同步在唯一常驻服务里每 15 分钟跑一次；一手 `WindowClock/WindowRules` 已并入 `YsGateLink`（ALLOW / SHORT 定时拉回 / BLOCK 立即弹页）。
- **仍未搬**：总控截图抽查（`takeScreenshot` 的抽样策略）仍保留在原 GuardService。

## 3.6 统一约束与题库出题（0.8.2 / P2）

- **统一名单**：`ConstraintStore` 把驾驶员拦截名单、总控 `blocked`、一手 `watched` 取并集，落 `filesDir/hub/constraints.json`；每条含 pkg / 分类 / 模式（直接拦 / 答题放行 / 只观察 / 放行）。
- **同步回三端**：直接拦写总控 `blocked`；答题放行写驾驶员 `blocked` 与一手 `watched`；驾驶员的最低字数/夜间禁用也随 Profile 走。
- **最严者胜**：`core/hub/PolicyEngine` 排序 BLOCK > GATE > OBSERVE > ALLOW；总控严管/总控时间会把模式升级为 BLOCK/HQ。
- **统一入口**：`HubPolicy` 在无障碍事件里先于三边旧链执行；命中 Profile 就只弹一个 `infra.gate.GateActivity`，旧链不再叠加。
- **四种模式**：统一拦截页新增 blocked 渲染（直接拦 / 总控时间：说明原因 + 回桌面 / 去长流，不给输入与放行）。
- **题库出题**：`QuestionBank` 从一手 Room 题库随机取一道；拦截出题优先用它，没有才走模型/模板（`QuestionRouter` 顺序：主线 → 题库 → 素材 → 模型 → 模板）。
- **P3/P4 地基**：`core/hub/ToolPolicy`（T0–T3、T3 确认、硬边界）与 `WakeRules`（每日 12 次、同因 30 分钟、夜间不开口）已带单测，供后续接入中枢 AI 与唤醒器。

## 3.7 中枢对话 / 主动唤醒 / 规划栏（0.8.3 / P3-P4 MVP）

- **中枢对话**（`hub/conductor`）：复用总控 `core.agent.ChatClient` 的工具调用循环；12 个工具：`get_stats`、`ledger_query`、`train_stats`、`bank_search`、`constraint_get/set`、`set_grant_minutes`、`live_start/status`、`schedule_wakeup`、`awareness_mode`、`undo`。
  - 收紧直接执行；放宽（模式降级、放行调高）返回 `PendingAction`，由界面弹 T3 确认。
  - `AiActionLog`：每次调用写 `filesDir/hub/ai_actions.jsonl`（id/工具/参数/等级/摘要/撤销信息）；T1/T2 可逐条撤销，撤销本身也记一条。
  - 入口：「首页 → 找中枢」「规划 → 问问中枢/开始周复盘」；ProactiveOverlay 的「聊两句」也进中枢。
- **主动唤醒**（`hub/wake/WakeScheduler`）：挂在 KeepAliveService 的 tick 上，纯本地判断，不调模型；触发包含额度 80%/100%、滑行 10 分钟、门连错 3 次、陪练结束、日复盘（21:30）、周复盘（周日 21:30）、AI 自定回访；统一走 `WakeRules` 的每日 12 次/同因 30 分钟/夜间不开口。
- **规划栏**（`ui/screens/PlanningScreen`）：统一壳第 3 栏改为「规划」，显示今日主线与部署、本周训练/娱乐/拦截/陪练、周复盘入口，以及四部/今日/计划深链。
- **仍是 MVP**：目标树/里程碑仍由总控计划页维护（规划栏是入口不是完整编辑器）；唤醒只出 L0 卡，不自动改计划；P3 工具只接了 12 个，计划中的另外 5 个尚未接。

## 5. 尚未完成 / 已知缺口

1. **源码刷新**：`legacy/` 是某一时刻的拷贝（含融合补丁）。上游一手/总控更新后，运行 `bash scripts/vendor-legacy.sh` 重新同步；脚本会在复制后自动应用 `patches/fusion-legacy.patch`（目前是总控权限状态桥）。
2. **长流引擎 P1（已落）**：`core/.../brain/` 五态估计、mood 引擎（加权 + 大随机 + 5–8% 尖峰 + 3–8 分钟持续）、主动决策（随机 120–240 秒心跳；同因/总 90 秒冷却；交互压力不插嘴；沉浸交给强制页；早晨第一次唤醒问今天钉哪件）；L0 悬浮卡（无悬浮窗权限退化为通知）；L1 沉默时 TTS 语音先开口（「我的」可关）；记忆消化（≥3 证据才写，可查看/删除/暂停，删除记墓碑不再回流）；周复盘自提权重（≥5 次证据、7 天自动过期、可恢复默认）；mood 权重已接 **总控真实信用分**（Boss 14 天账本）。已实测：悬浮卡、记忆消化、删除不回流、复盘采用/恢复默认。**边界**：自改只调语气权重，不改红线、宪章与账本；L1 只朗读不录音。
3. 一手窗口规则：`WindowClock/WindowRules` 已并入 `YsGateLink`（ALLOW / SHORT 定时拉回 / BLOCK 立即弹页）；原 1 秒 watch 循环改由 5 秒事件复查 + 20 秒 tick 承担。
4. **总控截图抽查**：Notion 同步已回到唯一常驻服务；`takeScreenshot` 的抽样策略仍在旧 GuardService（未注册）。
5. **总控哨兵 / healthwire**：旧 `SelfHeal`/`Watchdog` 已从唯一常驻循环移除（它们只认原 `GuardService`，融合后会误报「无障碍被关」）；`LocalGuardian` 保留。总控权限页/首页通过 `PermissionStatus.fusionA11y` 桥改看唯一服务，连接后不再显示「管不住你」。哨兵代码保留但不再跨 App 注册。
6. **统一壳**：四栏（首页/训练/四部/我的）已落地，聚合三套状态并提供深链入口，支持系统深浅色；伙伴对话内嵌到首页、完整「今天」信息流仍属后续。实现见 `app/src/main/kotlin/com/changliu/app/ui/`。
7. **真机 72h 验收**：全部未做（模拟器只能验证功能回路）。
8. **一手/总控决策链的真机实测**：两条链已在每次窗口事件执行且无崩溃，但还没有用各自配置（一手关注名单、总控严管/总控时间）做端到端断言。
