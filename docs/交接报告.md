# 长流（com.changliu.app）交接报告

> 给一个看不到仓库的 AI 读。目标是让你能在不读全部源码的前提下，判断这套系统在做什么、边界在哪、改哪里会炸。
> 仓库：https://github.com/aozhenyu666-cmyk/changliu （分支 `hub-closed-loop`），GPL-3.0。

---

## 一、它是什么

一个**离线自律/防御型 Android App**。不靠聊天刷存在感，靠三件事立住：

1. **拦**：你点开抖音/小红书/浏览器这类受控 App 时，无障碍服务立刻拉一个不可划掉的答题页盖住它，答对了才给几分钟。
2. **判**：总控用一套 14 天滚动信用分决定"这一关有多严"，信用越低关卡越硬。
3. **收**：AI（中枢）可以自主**收紧**约束，但放宽必须人工确认且延迟生效——单向棘轮。

核心设计取向是 **"只许收紧，不许哄骗"**：任何想通过对话放宽限制的操作，都要过 T3 人工确认层。

### 模块划分（`settings.gradle.kts`）

```
:core   纯 Kotlin / JVM，无 Android 依赖。所有"判定"逻辑都在这里，可单测
:infra  跨模块共用（fusion 钩子、密钥盒子、SSE）
:app    驾驶员底座 + 统一壳 + 拦截管道，applicationId = com.changliu.app
:ys     library 模块，namespace = com.yishou.app（一手）
:zk     library 模块，namespace = com.zongkong.app（总控）
legacy/ 一手与总控的原始源码树。ys/zk 不复制代码，而是用 legacySrc() 直接编译这里
```

**`ys/` 和 `zk/` 只是壳**：它们的 `sourceSets` 指向 `legacySrc("yishou"|"zongkong", ...)`，也就是**直接编译 `legacy/` 下的源树**。所以改一手/总控的代码要去改 `legacy/yishou` / `legacy/zongkong`，改 `ys/` `zk/` 目录本身通常没用（那里只有 `build.gradle.kts`）。

路径解析优先级（`ys/build.gradle.kts:80`、`zk/build.gradle.kts:73`）：

```kotlin
fun legacySrc(project: String, path: String): java.io.File {
    val local = file("$rootDir/legacy")
    val root = (findProperty("legacyRoot") as String?)   // -PlegacyRoot
        ?: System.getenv("LEGACY_ROOT")
        ?: if (local.isDirectory) local.absolutePath else "D:/code/src-ref"
    return file("$root/$project/$path")
}
```

仓库内 `legacy/` 优先，所以 CI 能编；本地如果把 `legacy/` 删了，就会回落到 `D:/code/src-ref` 这个仓库外路径——**这是唯一一处硬编码绝对路径，注意别踩**。

四个模块**同进程**运行，`ChangliuApp` 同时实现 `ZkHost` 和 `YishouApp`，所以 `GateDirector` 能直接 `ctx.applicationContext as? ZkHost` 拿到总控的 Store。

## 三、最关键的 8 个文件

按重要度排，改之前必须先读这些。

### 1. `core/src/main/kotlin/com/changliu/core/hub/GatePlan.kt` —— 关卡的唯一真相

纯函数，无 Android 依赖。**整套系统的"判刑标准"就在这一个文件里。**

```kotlin
enum class GateLevel(val n: Int, val label: String) {
    DRILL(1, "断点快答"), TRAIN(2, "专项闯关"),
    EVIDENCE(3, "证据核验"), LOCK(4, "绝对封锁"),
}

data class GateInput(
    val mode: AppMode = AppMode.GATE,
    val credit: Int = 70,        // 总控 14 天信用分
    val strict: Boolean = false, // 总控严管中
    val hqActive: Boolean = false, // 总控时间进行中
    val hold: Boolean = false,   // 专注锁：这轮不给放行
    val passCap: Int = 0,        // 总控允许的最大放行分钟，0 = 不限
    val opensToday: Int = 0,
    val baseMinutes: Int = 10,
    val companionMissed: Boolean = false, // 上次说好挂伴读没挂上
)

object GatePlanner {
    const val FLOOR = 40      // 低于此分直接封死
    const val WARY = 60
    const val NORMAL = 70
    const val MAX_MINUTES = 10
    const val COMPANION_PENALTY = 3
}
```

判定顺序（**顺序本身就是语义：先收紧，再谈宽松**）：

1. `mode == ALLOW` → 返回 `null`（不拦）
2. `hqActive` → LOCK / `GateMode.HQ`
3. `hold` / `strict` / `mode == BLOCK` → LOCK / `BLOCK`
4. `credit < 40` → LOCK / `BLOCK`
5. `credit < 60 || mode == OBSERVE` → L3 证据核验，1 轮，3 分钟，`companion=true`
6. `credit < 70 || opensToday >= 2` → L2 专项闯关，2 轮，5 分钟，`companion=true`
7. 其余 → L1 断点快答，1 轮，`baseMinutes`

放行分钟统一收口：`mins(m) = (minOf(minOf(m, cap), 10) - debit).coerceAtLeast(1)`，其中 `debit` 是伴读欠账 3 分钟。**封死档恒为 0 分钟，不参与扣减。**

单测：`core/src/test/.../GatePlanTest.kt`，12 项，覆盖"封死恒 0""passCap 压缩每一档""总控规则压过信用分""欠账扣到底留 1 分钟"。

### 2. `app/src/main/kotlin/com/changliu/app/hub/policy/GateDirector.kt` —— 唯一拦截管道

```kotlin
object GateDirector {
    data class ZkContext(credit, strict, hq, hold, passCap)

    fun zkContext(ctx): ZkContext        // 从 ZkHost.store + FusionHooks 取数
    fun zone(ctx): GatePlan?             // 壳层展示用：现在开一个受控 App 会到哪一关
    fun intercept(ctx, pkg): Boolean     // true = 这一层已接管，旧链别再弹
}
```

`intercept` 的流程：名单里没有 → `false`（交回旧规则）；`mode == ALLOW` → `false`；否则算 plan → 已可见就不重弹 → `Intercept.claimTrigger` 去抖 → `startActivity(GateActivity.intent(ctx, pkg, plan))`。

**历史包袱**：以前是三条链抢答（`ZkGateLink` / `YsGateLink` / `Intercept` 谁先返回 true 谁弹页），现在只剩这一条。`HubPolicy.kt` 已退化成一行 `@Deprecated` 委托，只为编译兼容，可以删。

### 3. `core/src/main/kotlin/com/changliu/core/hub/Constraints.kt` —— 最严者胜

```kotlin
enum class AppMode { ALLOW, OBSERVE, GATE, BLOCK }
enum class GateMode { GATE, BLOCK, HQ, YS_ENTRY }

object PolicyEngine {
    fun rank(mode): Int                    // ALLOW 0 < OBSERVE 1 < GATE 2 < BLOCK 3
    fun decide(opinions): ConstraintOpinion?  // maxByOrNull { rank }
    fun gateModeFor(mode, zkStrict, hqActive): GateMode?
}
```

三边（驾驶员/一手/总控）各给意见，合并取最严。**这条规则不许在任何地方被绕开重写。**

### 4. `app/.../hub/policy/ConstraintStore.kt` —— 名单落地

- 路径：`filesDir/hub/constraints.json`
- 结构：`{ apps: [{pkg, category, mode}], minChars, nightBan }`
- `importFromLegacy()`：首次启动把三份旧名单**取并集**
- `syncToLegacy()`：统一 Profile 单向写回三边旧配置（驾驶员 `blocking`、总控 `config.blocked`、一手 `watched`）
- 注意 `minChars` 被夹在 `15..200`

### 5. `app/.../infra/gate/GateActivity.kt` —— 闸门页

- 三种模式：`MODE_GATE` / `MODE_BLOCK` / `MODE_HQ`
- 入口：`GateActivity.intent(ctx, pkg, plan)`，extras 带 `pkg / level / rounds / minutes / companion / reason`
- L2 要连过 `rounds` 轮，`passedRounds` 进 `onSaveInstanceState`（转屏不丢）
- L3 多一个「去语音陪练拆一步」→ 拉 `com.yishou.app.window.WindowActivity`（`putExtra("startNow", true)`）
- 放行时 `Intercept.allow(this, target, minutes)`，然后 `gateLog("pass", ...)` 写账本
- 放行后若 `companion=true`：先 `CompanionDebt.mark(this)` 立字据，再拉 `ScrollActivity.startIntent(this, target)` 挂刷屏伴读
- Manifest 里 `excludeFromRecents=true` + 独立 taskAffinity + `singleTask`：**划不掉，这是和普通拦截 App 最大的区别**

### 6. `app/.../infra/a11y/ChangliuA11yService.kt` —— 唯一感知入口

- `onAccessibilityEvent` 里调 `GateDirector.intercept(ctx, pkg)`，是全系统**唯一**的拦截出口
- 另有 `passWatcher`：只有存在有效放行条（`blocking.allowedUntil` 未过期）时才每 `PASS_MS = 1_000L` 读一次前台包名，补"事件流被 ROM 吞掉"的秒切偷看；无放行条时完全不读窗口（省电）
- 已知上限：1 秒轮询，<1 秒切入切出仍可能漏。`shortcut: 1s 轮询，需要更高精度时改用无障碍事件 + 截帧校验`

### 7. `core/src/main/kotlin/com/changliu/core/hub/ToolPolicy.kt` + `WakeRules.kt`

- `ToolPolicy`：T0–T3 工具分级。**收紧直接执行，放宽需 T3 人工确认**，这是"单向棘轮"的代码表达
- `WakeRules`：主动唤醒节流 —— `DAILY_CAP = 12`、同因冷却 `30 分钟`、`23:00–06:00` 禁言。11 种触发源：`MORNING_UNLOCK` / `ENTERTAINMENT_80` / `ENTERTAINMENT_100` / `ACTION_OVERDUE` / `GLIDING_10MIN` / `LIVE_ENDED` / `GATE_FAIL_3` / `NO_PROGRESS_2H` / `DAILY_REVIEW` / `WEEKLY_REVIEW` / `AI_SCHEDULED`
- `QuestionRouter`：出题源优先级 `MAINLINE → BANK → MATERIAL → MODEL → TEMPLATE`

### 8. `legacy/zongkong/.../core/boss/Boss.kt` —— 信用分

```kotlin
const val BASE = 70
const val WINDOW_DAYS = 14
fun credibility(d, sessions, now, events) =
    (BASE + ledger(...).sumOf { it.delta }).coerceIn(0, 100)
```

计分表（`ledger()`，最近 14 天窗口）：

| 事件 | Δ |
|---|---|
| 说法属实 VERIFIED | +3 |
| 说法对不上 CONTRADICTED | **−12** |
| 说法说不清 VAGUE | −4 |
| 无法核实 UNVERIFIABLE | −1 |
| 约定做到 | +4 |
| 约定没做到 | **−10** |
| 总控时间做完 | +3 |
| 提前退出 | −5 |
| 主动问你 2 小时不回 | −3（一天最多 4 次） |
| 提醒后 45 分钟无动静 | −2（一天最多 3 次） |
| 15 分钟内回应 | +1（一天最多 4 次） |

`stanceOf`：≥80 TRUST / ≥60 NORMAL / ≥40 WARY / else STRICT。**态度取"信用算出来的"和"总控自己加的严格度"更严的那个。**

| 能力 | 声明 | 用户怎么给 |

| 读前台 App | `BIND_ACCESSIBILITY_SERVICE` | 系统设置里开无障碍（主路径） |

## 五、四部 → 一手的自动炼题管道

`app/.../hub/sync/MaterialSync.kt`：

- 读取总控脉络 `store.vein.value.nodes`，筛 `VStatus.HYPO`（未验证的假设）且未同步过的

- 写入一手素材池：`y.database.think().insertMaterial(Material(title, text, MaterialSource.TYPED, createdAt))`
- 去重：`SharedPreferences("hub_sync")` 的 `vein_seen` 字符串集合
- 单批上限 20 条，挂在 `KeepAliveService` 已有的 10 分钟后台 tick（该块本身跑在 `Thread{}` 上）

**刻意不做的事**：不自动生成四选一题卡。没有真实干扰项的题是假题，宁可让 `QuestionRouter` 用"素材 + 模型"现场出。

## 十、已知边界与坑（给接手者的警告）

1. **`HubPolicy.kt` 是死代码**，`@Deprecated` 一行委托。删它是安全的，但要先 grep 确认没有别的调用点。
2. **`ScrollService` 无法静默挂载**：`MediaProjection` 每次都要用户手点同意。当前策略是"拒绝 → 记欠账 → 下次放行扣 3 分钟"，不是"强制挂"。
3. **1 秒巡检的盲区**：<1 秒的切入切出会漏。
4. **收集箱仍依赖 Notion**（`inboxDb`）。这是"100% 独立"最后一条外部数据线，未本地化。
5. **两边历史不同源**：远端 `main` 是另一份 0.7.0 快照（`78f0411`），`hub-closed-loop` 是重新初始化的新历史。合并需要决策，不能直接快进。
6. **不要升级 `security-crypto` 到 1.1.x**，一手的 `MasterKeys` API 已在新版移除。
7. **一手/总控的真实源码在 `legacy/`**，`ys/` 和 `zk/` 只是编译壳（见第二节）。改 UI 或逻辑要去 `legacy/yishou` / `legacy/zongkong`。删了 `legacy/` 会回落到仓库外的 `D:/code/src-ref`。
8. 所有判定逻辑都在 `:core`，且都是纯函数。**如果你要改规则，只改 `:core` 并补测试**，不要改 `app` 层的分支——那是历史遗留的重复实现，早晚要删。

## 十一、一句话总结给接手的 AI

这套系统真正的创新不在 UI，在**「判定全部收口成纯函数 + 收紧自动、放宽需人工 + 拦截页划不掉」**这三点。剩下的都是围绕这三点的围栏。要评估它，先读 `GatePlan.kt`（判多重）和 `Boss.kt` 的 `ledger()`（为什么扣分），这两个文件决定了整套系统的性格。
